# Flyby inbox

During unrelated work, record a concrete non-blocking discovery as a new file
under `inbox/` and immediately return to the authorized task.

- Do not read existing reports, search for duplicates, investigate further, or
  design a solution before adding one.
- Use a unique date-and-slug filename and at most five short lines.
- State `observed` or `suspected`, the issue, a rediscovery pointer, and why it
  did not block current work.
- Raise correctness, safety, and current-milestone blockers immediately instead.

After explicit milestone acceptance and before the next milestone alignment,
read and triage the whole inbox. Deduplicate, discard weak reports, and promote
retained work to the relevant durable page. Triage never authorizes a fix.
